# RS-007 실제 관리자 모바일 검증 — TC-007-13

상태: **NOT RUN**. 실제 iPhone/Android 및 승인된 관리자 접속 환경이 제공되지 않았다. Chromium의 360/390/1280px 자동화 결과는 실기기 Safari/Chrome 또는 mTLS 검증을 대체하지 않는다.

격리된 스테이징의 테스트용 DB와 합성 예약 데이터만 사용한다. 실제 서비스 DB·인증서·키를 변경하지 않는다. 관리자 접속은 유효한 테스트 인증서 또는 승인된 격리 접속 환경으로 준비하며, 공개 사이트에 관리자 링크나 로그인 화면을 추가하지 않는다. 프록시·인증서 검증은 RS-008에서 별도로 수행한다.

| 환경 | 기기/OS/브라우저 실제 버전 | 접속/인증 방식 | 실행 일시(KST) | 결과/증거 |
|---|---|---|---|---|
| iPhone Safari | 미제공 | 미제공 | 미실행 | NOT RUN |
| Android Chrome | 미제공 | 미제공 | 미실행 | NOT RUN |

1. 인증 없는 공개/관리자 컨텍스트에서 `/admin` 및 관리자 API가 거부되는지 확인한다. 유효한 테스트 접근 컨텍스트에서는 관리자 페이지를 열고 가로 스크롤·확대·키보드·포커스·터치 대상 크기를 확인한다.
2. 미래 두 날짜를 등록하고 목록·달력·이력과 서버 데이터를 대조한다. 이름/메모/날짜를 수정한다. 12월/1월처럼 월을 넘는 예약을 한쪽 월 목록에서 열어 전체 날짜가 표시되고 이름만 바꿀 때 다른 월 날짜도 보존되는지 확인한다.
3. 예약 취소 확인을 한 번 거절하고 서버 요청/변경이 없는지 확인한다. 다시 승인하여 단 한 번 취소되고 점유가 해제되는지 확인한다. 차단일 등록·기존 예약 날짜와 일괄 충돌·차단 해제 확인에도 같은 절차를 수행한다.
4. 다른 세션이 편집 대상 날짜를 먼저 점유한 뒤 저장한다. 409 안내, 수정본/원본 보존과 새로고침을 확인한다. 서버 상태와 이력을 대조한다.
5. 로그 다음/이전 이동과 예약 기간 변경을 확인한다. 기간을 줄여도 기존 예약/차단이 유지되는지 확인한다. 잘못된 기간 값은 변경되지 않아야 한다.
6. 토큰 만료 또는 접근 만료 후 변경 요청에 403 안내가 표시되고 성공 표시/자동 재제출이 없는지 확인한다. 명시적으로 접근/CSRF를 새로 확인한 뒤 수동 제출한다. CSRF는 메모리에만 보관되며 브라우저 영구 저장·URL·로그에 없어야 한다. 토큰 원문을 증거에 남기지 않는다.
7. 격리 환경에서 네트워크 단절/503을 유도해 입력 보존·버튼 복구·중복 제출 방지를 확인한다. 응답 손실은 실제 변경 성공 여부가 불명확하므로 목록/이력 확인 전 재제출하지 않는다.
8. 합성 HTML 형태 이름/메모를 목록·편집에서 확인한다. 문자열로 표시되고 실행되지 않아야 한다. 민감 응답은 no-store이며 뒤로가기/새로고침에서 데이터·토큰을 영구 보관하지 않아야 한다.

각 단계에 실제 기기·OS·브라우저 버전, 인증 환경, 실행 일시, 기대/실제 결과, 실패 재현과 민감정보 없는 증거를 기록한 후 `qa/reports/RS-007.md`와 CSV를 갱신한다. 미실행 항목을 PASS로 기록하지 않는다. 장치/OCI/운영 승인이 남아 있으면 공개 릴리스는 NO-GO다.

## 자동화 환경과 구분

`tests/e2e/test_admin_ui.py`는 테스트 전용 Python 인증 주입과 브라우저의 `https://admin.test` 요청을 실제 loopback HTTP/SQLite 서버로 전달하는 테스트 어댑터를 사용한다. 브라우저가 생성한 Origin과 CSRF를 그대로 검증하고 앱의 Host/Origin/CSRF 검사도 유지한다. 이 어댑터는 테스트 파일에만 있으며 실제 TLS/mTLS 종단·외부 프록시 검증 증거가 아니다. 모든 DB와 clock/access 제어 파일은 케이스별 임시 디렉터리에만 생성된다.
