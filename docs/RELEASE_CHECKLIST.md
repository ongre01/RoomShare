# MVP 공개 판정 — RS-009

**NO-GO.** 승인된 범위는 공유 Ubuntu에서의 격리 검증뿐이다. [검증 보고서](../qa/reports/RS-009.md)와 [RS-008 인계](../qa/reports/RS-008.md)를 함께 확인한다. 아래 항목을 로컬 pytest 성공으로 대신하거나, 체크리스트만으로 서비스를 공개하지 않는다.

| 남은 확인 | 누가 / 어디서 | 필요한 증거 |
|---|---|---|
| 서비스 최소 권한·재시작·자동 백업 | 운영자 / 전용 Ubuntu, 합성 DB | TC-008-03/10/14: 서비스 UID·소켓·쓰기 경계, 재시작 전후 데이터/권한, 타이머 실제 발화와 백업 실패 기록. |
| 외부 접근 경계 | 운영자 / 서버 밖의 승인된 클라이언트 | TC-008-08 및 TC-009-05: 사용자·관리자 HTTPS, 인증된 관리자만 접근, 외부 백엔드 8000 거부. 공개 IPv6가 있으면 함께 확인. |
| 모바일 실제 장치 | QA / iOS Safari, Android Chrome | TC-005-13, TC-007-13, TC-009-08: [사용자](../tests/manual/public-ui.md)·[관리자](../tests/manual/admin-ui.md) 흐름과 기기·OS·브라우저별 결과. |
| 실제 OCI | 운영자 / 승인된 OCI 스테이징 | TC-008-15/16, TC-009-10: DNS/TLS/mTLS, 보안 목록·NSG·OS 방화벽, 재시작 및 격리 복원, 자원·지연·오류율 실측. [배포 실행서 §5](DEPLOYMENT.md#5-승인-환경에서-남기는-증거-로컬과-oci-별도) 참조. |
| 정책·장애 시 복귀·공개 승인 | 운영자 | [미확정 정책](DECISIONS.md), 공개 범위와 관리자 인증서 관리, 백업 보존·별도 보관·RPO/RTO, 이전 릴리스와 호환되는 DB 및 복귀 연습, 성능 기준과 비용을 검토하고 결정을 기록. |

같은 후보 커밋에 대해 환경·시간·명령·종료 코드와 비밀 없는 결과를 남긴다. 실행 코드·설정·의존성이 바뀌면 해당 케이스와 전체 회귀를 다시 검증한다. 필수 실패 또는 미검증이 남으면 계속 NO-GO. 최종 공개는 별도 운영자 승인 사항이며 이 티켓에서 배포·태그·push·merge하지 않는다.
