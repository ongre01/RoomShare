# 요구사항
## 확정 (사용자 명시)
| ID | 요구사항 |
|---|---|
| FR-01 | 개인 원룸 1개 전체를 날짜별로 다른 사람이 사용한다. |
| FR-02 | 예약 단위는 1일이다. |
| FR-03 | 모바일 웹과 OCI를 사용한다. |
| FR-04 | 로그인 및 회원가입은 없다. |
| FR-05 | 관리자와 사용자 페이지를 주소로 분리한다. |
| FR-06 | 사진, 가격 기능은 없다. |

## MVP 제안 (승인 전 임시 설계)
| ID | 요구사항 |
|---|---|
| FR-07 | 월별 캘린더, 월 이동, 복수 날짜 선택, 날짜 상태 표시 |
| FR-08 | 이름/닉네임 필수, 메모 선택, 즉시 예약 확정 |
| FR-09 | 날짜 중복 금지, 과거일 예약 금지, 복수일 원자적 처리 |
| FR-10 | 무작위 취소 토큰으로 사용자 예약 취소 |
| FR-11 | 관리자 예약 조회/등록/수정/취소 |
| FR-12 | 관리자 예약 불가일 등록/해제 |
| FR-13 | 변경 이력, 운영 설정 |
| NFR-01 | 모바일 360px 폭에서도 가로 스크롤 없이 사용 |
| NFR-02 | HTTPS, 관리자 UI/API 접근 제한, 개인정보 최소화 |
| NFR-03 | 경량 단일 서버, 자동 백업, 복원 검증 |
| NFR-04 | 동시에 같은 날짜 예약 시 정확히 한 요청만 성공 |

제외: 결제, 사진, 계정, 다중 원룸, 리뷰, 승인 워크플로, 네이티브 앱. PWA는 선택 확장.
