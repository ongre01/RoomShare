## 결함 / 미해결 사항

- 수정 완료(제품): JSON의 단독 Unicode surrogate 이름이 문자열 검증을 통과해 SQLite 인코딩 단계에서 500이 될 수 있었다. API 문자열 검증에서 422로 거부하도록 수정하고 이름/메모 회귀 입력을 추가했다. DB는 변경되지 않는다.
- 수정 완료(신규 테스트 설정): HTTPX json 인자의 serializer가 surrogate를 전송 전에 거부하므로 escaped JSON bytes/content로 보내 실제 서버 검증을 시험하도록 수정했다. 기존 assertion/정책 완화 없음.
- 수정 완료(신규 테스트 가정): 깊이 1,100의 완전한 배열이 파서에서 실패한다고 가정했지만 설치 Python은 파싱 후 스키마 422로 처리했다. 실제 잘못된 중첩 JSON(닫는 괄호 누락)의 400과 완전한 배열의 스키마 422를 각각 검증하도록 입력을 분리했다. 파서 예외는 별도로 400으로 정제한다.
- 실제 HTTP 검증: 임시 DB를 migration한 뒤 loopback 임시 포트에서 `uvicorn ... --no-access-log`로 실행했다. 달력→생성→충돌→취소→재예약 및 400/422/no-store/민감정보·로그 부재/DB 무결성/프로세스 종료와 임시 파일 정리를 확인했다. 초기 임시 검증 코드는 graceful shutdown 후 Uvicorn의 SIGTERM 반환(-15)을 실패로 판단하여 종료 1이었다. 제품 수정 없이 0 또는 -15와 두 shutdown 로그를 함께 검증하도록 수정한 최종 실행은 종료 0이다. 이는 실제 프록시·TLS 테스트가 아니다.
- RS-004의 필수 완료 조건·로컬 14개 TC·전체 회귀 게이트를 충족했으며 차단 사항은 없다. 요청 제한은 프로세스별 고정 시간창으로 재시작 시 초기화되고 한 사용자도 공용 한도를 소진할 수 있다. 운영 단일 worker 및 프록시 보완을 전제로 하며 운영 수치는 임시값이다.
- 전체 공개 릴리스는 미완료다. 사용자/관리자 UI·접근 제어·실제 프록시/TLS/장치/OCI/백업 검증과 정책 승인은 후속 범위로 남는다.
