# Agent 실행 가이드

개인 Ubuntu의 Git 저장소에서 VS Code Remote SSH로 작업한다. 이 패키지는 구현 전 설계와 티켓이며 실행 가능한 앱은 아니다. 원본 문서와 기존 요구사항을 유지했다.

## 실행 순서
1. 저장소에 이 패키지를 반영한다. 기존 작업이 있다면 덮어쓰기 전 diff를 비교한다.
2. Agent에게 아래 공통 시작 프롬프트를 전달한다. Agent가 저장소 파일을 읽을 수 있어야 한다.
3. 각 티켓 완료 보고와 테스트 결과를 검토한 후 다음 티켓을 지시한다. RS-003까지 순차 진행, 이후 RS-004→005 및 RS-006→007은 병렬 가능. 공통 파일 변경은 통합 전에 조율한다.
4. RS-008 로컬 배포/복원 검증, OCI 이전은 별도 승인 및 환경 제공 후 진행. RS-009에서 릴리스 판정. RS-010은 선택.

## v3 진입점 및 짧은 시작 프롬프트
저장소 루트에서 Agent를 실행한다. `CLAUDE.md`는 `@AGENTS.md` 및 `@prompts/COMMON.md`를 참조한다. Codex는 `AGENTS.md`에서 지정한 공통 지침과 대상 파일을 읽도록 구성한다. Agent 버전/설정에 따라 로딩 여부가 달라질 수 있으므로 실제 세션에서 확인한다.

### 구현
```text
RS-001 티켓을 구현해줘. AGENTS.md와 prompts/COMMON.md를 적용하고
대상 티켓/프롬프트/QA 명세에 따라 실제 구현 및 테스트를 수행해줘.
필수 완료 조건을 충족한 경우에만 DONE 처리해줘.
```
### QA
```text
RS-001 티켓의 QA를 수행해줘. AGENTS.md와 prompts/COMMON.md,
qa/specs/RS-001.md에 따라 테스트를 작성·실행하고 실제 증거를 기록해줘.
제품 코드 수정이 필요하면 별도로 보고하고 자동으로 수정하지 마.
```
### 독립 리뷰
```text
RS-001 티켓을 리뷰해줘. AGENTS.md, prompts/COMMON.md,
prompts/REVIEW.md에 따라 구현 및 테스트를 검토하고 재실행해줘.
소스/테스트/티켓 상태/Git을 변경하지 말고 리뷰 결과를 보고해줘.
```
대상 번호만 바꿔 사용할 수 있다. 후속 티켓은 자동으로 착수하지 않는다.

## 로딩 확인 (최초 세션 및 설정 변경 후)
- 저장소 루트에서 `claude` 또는 `codex`를 실행한다. Claude Code의 `/memory`가 지원되는 버전이면 로드된 프로젝트 지침을 확인한다.
- 두 Agent 모두 아래 읽기 전용 프롬프트로 실제 파일 접근 및 지침 적용 여부를 확인한다. 답변만으로 자동 로딩이 입증되는 것은 아니므로 도구 실행 기록이나 로드된 지침 목록도 확인한다.
```text
파일을 수정하지 말고 AGENTS.md와 prompts/COMMON.md의 내용을 실제 확인해줘.
읽은 파일 경로, 대상 티켓별 필수 문서 목록, 테스트 PASS/DONE 조건,
운영 서버와 Git 변경 제한을 보고해줘. 읽지 못한 파일은 명시해줘.
```
- 자동 로딩이 확인되지 않으면 파일을 명시적으로 읽으라고 지시한다. 파일 접근 권한 자체가 없으면 작업을 진행하지 않는다.
- 이 패키지에서는 실제 Claude Code/Codex 실행 환경 검증은 수행하지 않았다.

## 설계 가정 및 확인 사항
- 원본 DECISIONS.md의 정책은 미확정 상태를 유지한다. 오늘 포함 90일의 범위는 today~today+89일로 해석했다. 사용자 취소는 당일 및 과거가 포함된 예약은 불가라는 원본 임시 정책을 적용한다.
- 기간 밖 미래 날짜는 기존 API의 max_date로 선택을 제한한다. 새로운 상태 enum은 추가하지 않는 방향으로 작성했다.
- 관리자 과거 날짜 변경/취소 제한, 관리자 응답 no-store, CSRF 방식, 제한 수치, 백업 보존 기간은 상세화 과정의 제안 또는 후속 결정 항목이다. 운영 전 승인 필요.
- 원본 DESIGN의 공개 응답 토큰 제외 문구는 API의 예약 생성 응답에 한해 본인 토큰 1회 반환으로 해석했다. 문서 충돌은 RS-003/004에서 정리한다.
- 별도 주소만으로 관리자 보안을 확보할 수 없다. mTLS를 기본 제안으로 유지하고 실제 프록시/직접 접근 차단 검증을 요구한다.
- Git 브랜치 이름과 예상 구현 파일은 제안이다. 실제 코드 구조에 따라 변경 가능하다.
- 실제 소스 구현, 테스트, OCI 연결, 배포는 이 패키지에서 수행하지 않았다. 모든 티켓은 TODO다.

## 전체 경로를 명시하는 대체 프롬프트 (v2 호환)
```text
AGENTS.md, README.md, docs/ 전체, tickets/INDEX.md,
prompts/COMMON.md, tickets/RS-001.md, prompts/RS-001.md,
qa/specs/RS-001.md, qa/TEST_CASES.csv, qa/TRACEABILITY.md, qa/REPORT_TEMPLATE.md를 읽어라.
RS-001만 실제 구현하고 테스트 코드까지 작성하라.
TC별 실제 결과/명령/종료 코드를 qa/reports/RS-001.md와
qa/TEST_CASES.csv에 기록하라. 전체 회귀와 코드 리뷰를 수행하라.
필수 미실행 항목을 PASS/DONE으로 처리하지 말고,
운영 변경/원격 push/merge/후속 티켓 시작을 하지 마라.
```
번호만 변경해 다음 티켓에 사용한다. 상세 케이스의 수치 및 추가 도구는 검증 계획의 제안이다. 실제 OCI/장치 승인 및 환경이 필요하다.
