# RS-002 실행 프롬프트

당신은 RoomShare 프로젝트의 소프트웨어 개발 Agent다. 현재 저장소에서 **RS-002 — SQLite 스키마 및 마이그레이션**만 실제 구현하라. 단순 설계 제안이나 코드 예시만 작성하지 말고, 필요한 파일을 수정하고 테스트를 실행하라.

## 먼저 읽을 파일
`AGENTS.md`, `README.md`, `docs/REQUIREMENTS.md`, `docs/DECISIONS.md`, `docs/DESIGN.md`, `docs/API.md`, `docs/DEPLOYMENT.md`, `tickets/INDEX.md`, `tickets/RS-002.md`, `prompts/COMMON.md`.
공통 작업 지침을 적용하며 선행 티켓(RS-001)의 실제 완료 및 산출물을 검증하라. 사용자 변경 보존 및 테스트 전용 DB 사용. 운영 서버 변경/push/merge 금지.

## 이번 작업의 목표
예약과 차단의 공유 날짜 고유 제약 및 데이터 보존 가능한 DB 기반 구현.

## 수행할 작업
1. DESIGN에 지정된 reservations, reserved_dates, reservation_logs, settings, schema_migrations 테이블을 SQL 마이그레이션으로 구현한다. UUID 예약 ID, 예약 상태 CHECK, 날짜 PRIMARY KEY, FK, RESERVED/BLOCKED와 reservation_id null 여부의 CHECK를 적용한다. 실제 달력 날짜의 유효성은 서비스에서 별도 검증한다.
2. 취소 토큰 해시만 저장할 컬럼을 만든다. 관리자 생성 예약의 토큰은 외부 노출 없이 처리할 수 있도록 RS-003/006 계약에 설명한다. 토큰이나 이름을 담은 로그는 최소화하고 토큰은 절대 기록하지 않는다.
3. 연결 생성/정리 helper와 BEGIN IMMEDIATE 트랜잭션 컨텍스트를 구현한다. 연결별 foreign_keys=ON 및 busy_timeout, 파일 DB의 WAL 적용 확인. 예외 시 rollback 및 close 보장. 다중 연결 테스트는 실제 임시 파일 DB 사용.
4. 순서 있는 버전 마이그레이션, 적용 기록, 재실행 안전성, 실패 원자성을 구현한다. 스키마 업그레이드 시 기존 데이터 삭제 금지. 초기 기본 설정의 출처와 우선순위를 명확히 한다.
5. 조회에 필요한 인덱스(예약 ID, 로그 조회 등)를 추가하고 명시적 마이그레이션 실행/검증 명령을 문서화한다. 운영 DB 자동 삭제 또는 다운그레이드 금지.

## 변경 범위
app/db.py, app/migrations/, scripts/migrate.py, tests/test_db.py, tests/test_migrations.py, docs/DESIGN.md
파일명은 제안이며 실제 저장소 구조에 맞추되 범위를 확대하지 마라.

## 테스트 요구
- 빈 DB 초기화 및 동일 마이그레이션 두 번 실행, 버전 중복 없음.
- 기존 레코드 생성 후 재실행해 데이터 유지, 실패 마이그레이션에 대한 롤백.
- 중복 날짜, 잘못된 FK, 잘못된 type/null 조합, 잘못된 예약 상태 거부.
- 독립 연결 각각의 PRAGMA 및 writer 경합/rollback/연결 정리 확인.
- DB 무결성 검사와 전체 pytest.

## 심화 실행 절차 (v2)
반드시 `docs/TEST_PLAN.md`, `qa/specs/RS-002.md`, `qa/REPORT_TEMPLATE.md`, `qa/TRACEABILITY.md`를 추가로 읽어라. 다음 지침은 기존 티켓의 구현 범위와 함께 적용한다.

1. SQL migration 파일에 version 순서를 명시하고 적용 전후 스키마와 적용 기록을 검사한다. transaction 경계를 깨뜨리는 SQL 실행 방식에 주의한다. migration 실패 테스트에는 부분 DDL과 DML 모두 포함한다.
2. `connect(db_path)`와 `write_transaction()`의 소유권(호출자/컨텍스트), 커밋/롤백/close 책임을 정한다. DB busy와 constraint 오류를 구분할 수 있도록 상위 서비스에 예외 계약을 넘긴다. 임의 재시도로 오류를 숨기지 않는다.
3. DB 검증에는 실제 SQLite 파일을 사용한다. 날짜 컬럼은 서비스가 정규화된 문자열을 제공한다는 전제를 명시하고 DB PK/CHECK/FK의 책임과 분리한다. `PRAGMA integrity_check`와 `PRAGMA foreign_key_check` 모두 실행한다.
4. 상태·점유 불변식 검증 helper를 테스트에 준비한다: 날짜당 최대 1개, RESERVED는 유효한 CONFIRMED 예약 참조, BLOCKED는 reservation_id NULL, CANCELLED는 현재 점유 없음. 애플리케이션 레벨 불변식은 RS-003/004/006에서 검사한다.

### 구현 및 테스트 수행 순서
1. 선행 산출물과 현재 코드를 확인하고 이번 티켓의 파일/인터페이스/테스트 계획을 작성한다. 아직 구현되지 않은 후속 기능은 범위에 넣지 않는다.
2. 다음 명세를 기준으로 가능한 자동화 테스트를 작성한다. 미구현 기능의 실패 또는 기존 기준선을 실제 실행하고, 테스트의 실패 이유를 기록한다. 존재하지 않는 테스트를 실행했다고 주장하지 않는다.
3. 기능을 구현하고 정상/오류/경계 케이스를 반복 실행한다. 실제 SQLite가 필요한 테스트에 mock DB를 쓰지 않는다. 수동 케이스는 실제 환경에서만 PASS 처리한다.
4. 명세의 기대 결과를 상태·응답·DB/로그 등 해당 관찰 지점에서 직접 검증한다. 관련 TC ID를 테스트명, 파라미터 ID 또는 보고서에 연결한다.
5. 아래 목록 전체와 상세 명세의 사전 조건·절차를 확인한다. 케이스를 임의 삭제하거나 skip으로 통과시키지 않는다.
- `TC-002-01` [db/local] 초기 마이그레이션 → 정의된 5개 테이블, 인덱스/제약 및 적용 버전 존재
- `TC-002-02` [db/local] 재실행 보존 → 레코드와 적용 버전 불변; 중복 버전 없음
- `TC-002-03` [db/local] 업그레이드 원자성 → 실패 버전 미기록, 부분 DDL/DML 없음, 기존 레코드 보존
- `TC-002-04` [db/local] 날짜 PK 중복 → 모두 IntegrityError, 기존 행 유지
- `TC-002-05` [db/local] FK 및 타입 CHECK → 모두 거부; 올바른 조합만 허용
- `TC-002-06` [db/local] 예약 상태 CHECK → INVALID 거부, 정상 상태 허용
- `TC-002-07` [db/local] 연결별 PRAGMA → 각 연결 foreign_keys=1, 설정한 timeout, WAL 파일 DB 확인
- `TC-002-08` [db/local] 예외 롤백 → 새 연결에서 예약/점유/이력 0건; 잠금 해제
- `TC-002-09` [db/local] writer 경합 → 정해진 busy 오류, A 해제 후 성공, 무한 대기 없음
- `TC-002-10` [db/local] 무결성 및 연결 정리 → ok, FK 위반 0, 정상 종료 및 다음 쓰기 가능
- `TC-002-11` [db/local] 설정 초기값 보존 → 사용자 변경 값을 기본값으로 덮어쓰지 않음
6. 대상 테스트 및 전체 pytest를 실행하고 결과/종료 코드/수집 건수/실패·skip을 기록한다. 브라우저, Nginx, OCI 등 별도 테스트는 실제 명령 및 환경 증거를 남긴다.
7. 자기 변경에 대한 코드 리뷰를 수행한다. 요구사항 및 API 계약, 오류 경계, 데이터 무결성, 보안, 불필요한 의존성, 테스트 독립성, 변경 범위를 확인하고 발견한 결함은 회귀 케이스와 함께 수정한다.
8. `qa/REPORT_TEMPLATE.md`를 사용해 `qa/reports/RS-002.md`를 작성하고 `qa/TEST_CASES.csv`에서 자신의 케이스 상태를 갱신한다. `tickets/RS-002.md` 및 INDEX의 완료 증거도 기록한다. 실행되지 않은 외부 환경 검증은 NOT RUN/BLOCKED로 남긴다.
9. 기존 완료 조건과 TEST_PLAN의 품질 게이트를 모두 충족할 때만 DONE으로 판단한다. 실제 Git 권한이 있을 때만 자기 변경을 커밋하고 push/merge/후속 티켓 착수는 하지 않는다.
