# RS-005 실행 프롬프트

당신은 RoomShare 프로젝트의 소프트웨어 개발 Agent다. 현재 저장소에서 **RS-005 — 사용자 모바일 웹**만 실제 구현하라. 단순 설계 제안이나 코드 예시만 작성하지 말고, 필요한 파일을 수정하고 테스트를 실행하라.

## 먼저 읽을 파일
`AGENTS.md`, `README.md`, `docs/REQUIREMENTS.md`, `docs/DECISIONS.md`, `docs/DESIGN.md`, `docs/API.md`, `docs/DEPLOYMENT.md`, `tickets/INDEX.md`, `tickets/RS-005.md`, `prompts/COMMON.md`.
공통 작업 지침을 적용하며 선행 티켓(RS-004)의 실제 완료 및 산출물을 검증하라. 사용자 변경 보존 및 테스트 전용 DB 사용. 운영 서버 변경/push/merge 금지.

## 이번 작업의 목표
로그인 없이 스마트폰에서 날짜 선택, 예약, 취소가 가능한 공개 UI 구현.

## 수행할 작업
1. `/` 페이지에 월 이동(이전/다음/오늘), 요일 7열 달력, 상태 범례, 선택 목록/개수, 이름/선택 메모, 예약 버튼, 결과 및 취소 폼 구현. 사진/금액/계정/관리자 링크 없음.
2. 달력 응답의 today/min_date/max_date를 사용하고 브라우저 UTC 변환으로 날짜를 하루 이동시키지 않는다. 날짜 문자열을 키로 Set 등에서 선택 유지, 정렬 표시, 개별 해제 및 전체 해제. 예약/차단/과거/기간 밖 날짜는 선택 불가. 색 외 텍스트/기호 및 접근성 이름 제공.
3. 월 이동 중 느린 이전 응답이 최신 화면을 덮지 않도록 처리. 선택된 다른 월의 날짜도 제출한다. 충돌 409 시 서버가 반환한 충돌 날짜를 표시하고 관련 월의 상태를 다시 확인, 가능한 선택은 보존한다. 이미 제출한 요청을 자동 재전송하지 않는다.
4. 입력 검증, 로딩/버튼 비활성화/중복 클릭 방지, 네트워크 오류/429/503/성공/충돌 표시. 이름/메모는 안전한 textContent 또는 템플릿 escape 사용. HTML 삽입 금지.
5. 성공 후 예약 ID/취소 토큰을 한 번만 표시하고 사용자가 직접 보관할 수 있는 복사 기능 제공. 토큰을 localStorage/sessionStorage, URL, 로그에 저장하지 않는다. 취소 폼은 ID+토큰 입력과 확인, 결과 및 달력 갱신을 제공한다.
6. 360px 모바일 우선, 키보드/터치 조작, 레이블/포커스/상태 공지 지원. 프레임워크/외부 CDN 필수 의존성 금지.

## 변경 범위
app/templates/index.html, app/templates/base.html, app/static/css/public.css, app/static/js/public.js, app/routers/public.py, tests/test_public_page.py, tests/manual/public-ui.md
파일명은 제안이며 실제 저장소 구조에 맞추되 범위를 확대하지 마라.

## 테스트 요구
- 360px/390px/데스크톱 뷰포트 가로 overflow 여부, 버튼 터치/키보드 조작.
- 이전/다음 월 이동, 연도 경계, 비연속/복수 월 선택 유지 및 해제.
- 금지 날짜 선택 차단, 기간 밖 AVAILABLE 상태도 선택 불가.
- 정상 예약, 중복 클릭, 충돌 후 갱신, API 429/503/네트워크 오류, 취소 성공/실패.
- 느린 월 조회 응답 역전, HTML 입력 안전 표시, 토큰 저장/URL/캐시 부재.
- Safari/Chrome 실제 확인 여부 명시. 실제 브라우저 없으면 NOT RUN 기록.

## 심화 실행 절차 (v2)
반드시 `docs/TEST_PLAN.md`, `qa/specs/RS-005.md`, `qa/REPORT_TEMPLATE.md`, `qa/TRACEABILITY.md`를 추가로 읽어라. 다음 지침은 기존 티켓의 구현 범위와 함께 적용한다.

1. 상태 모델을 월/선택 Set/입력/요청 중/오류/성공으로 분리한다. 날짜 키는 문자열 그대로 사용하며 today/min_date/max_date는 서버를 신뢰한다. 화면에서 금지 날짜를 막아도 서버 재검증을 생략하지 않는다.
2. 월 요청은 증가하는 요청 ID 또는 AbortController로 최신 응답만 반영한다. 다른 월의 선택을 유지하되 새로 금지된 날짜는 사용자에게 알리고 정리한다. 응답 손실과 명시적 409를 구분한다.
3. 성공 상태에만 토큰을 표시하며 복사 실패 시 수동 복사 안내를 제공한다. 새로고침 후 복구되지 않는다는 안내, 취소에 ID와 토큰 모두 필요하다는 설명을 넣는다. 콘솔/URL/storage에 기록 금지.
4. 실제 브라우저 E2E에서 API를 통째로 mock한 테스트와 실제 서버 연동 테스트를 구분한다. 오류/응답 역전은 intercept로 재현 가능하지만 정상 예약·취소·충돌은 실제 파일 DB와 서버로 검증한다.

### 구현 및 테스트 수행 순서
1. 선행 산출물과 현재 코드를 확인하고 이번 티켓의 파일/인터페이스/테스트 계획을 작성한다. 아직 구현되지 않은 후속 기능은 범위에 넣지 않는다.
2. 다음 명세를 기준으로 가능한 자동화 테스트를 작성한다. 미구현 기능의 실패 또는 기존 기준선을 실제 실행하고, 테스트의 실패 이유를 기록한다. 존재하지 않는 테스트를 실행했다고 주장하지 않는다.
3. 기능을 구현하고 정상/오류/경계 케이스를 반복 실행한다. 실제 SQLite가 필요한 테스트에 mock DB를 쓰지 않는다. 수동 케이스는 실제 환경에서만 PASS 처리한다.
4. 명세의 기대 결과를 상태·응답·DB/로그 등 해당 관찰 지점에서 직접 검증한다. 관련 TC ID를 테스트명, 파라미터 ID 또는 보고서에 연결한다.
5. 아래 목록 전체와 상세 명세의 사전 조건·절차를 확인한다. 케이스를 임의 삭제하거나 skip으로 통과시키지 않는다.
- `TC-005-01` [e2e/local] 모바일 레이아웃 → 가로 overflow 없음, 모든 주요 버튼 조작 가능
- `TC-005-02` [api/local] 제외 기능 확인 → 계정/로그인/사진/가격/결제/관리자 링크 없음
- `TC-005-03` [e2e/local] 복수 월 선택 → 두 날짜 선택 유지, 정렬/개수 정확, 해제 가능
- `TC-005-04` [e2e/local] 금지 날짜 → 선택 목록 미변경; 상태를 색 외 정보로 구분
- `TC-005-05` [e2e/local] 예약 성공 → 201 후 성공 UI, ID/토큰 한 번 표시, 달력 갱신
- `TC-005-06` [e2e/local] 중복 클릭 → 네트워크 생성 요청 1개, 처리 중 비활성화
- `TC-005-07` [e2e/local] 충돌 후 복구 → 409 안내, 관련 월 재조회, 충돌 날짜 표시 및 나머지 선택 유지, 자동 재제출 없음
- `TC-005-08` [e2e/local] 응답 역전 → 최신 1월 화면 유지, 선택 상태 오염 없음
- `TC-005-09` [e2e/local] 오류 및 입력 보존 → 적절한 안내, 성공 거짓 표시 없음, 입력 보존, 결과 불명 시 새 제출 자동 실행 금지
- `TC-005-10` [e2e/local] 취소 UI → 성공 시 달력 갱신, 실패 시 명확한 안내 및 점유 유지
- `TC-005-11` [e2e/local] 토큰 및 XSS → 스크립트 실행 없음, 토큰 URL/영구 및 세션 storage/로그 미저장
- `TC-005-12` [e2e/local] 접근성 기본 → 포커스 확인 가능, 상태 공지, 비활성 날짜 선택 불가
- `TC-005-13` [manual/device] 실제 모바일 브라우저 → 기기/OS/브라우저 기록; 에뮬레이션과 별도 증거
6. 대상 테스트 및 전체 pytest를 실행하고 결과/종료 코드/수집 건수/실패·skip을 기록한다. 브라우저, Nginx, OCI 등 별도 테스트는 실제 명령 및 환경 증거를 남긴다.
7. 자기 변경에 대한 코드 리뷰를 수행한다. 요구사항 및 API 계약, 오류 경계, 데이터 무결성, 보안, 불필요한 의존성, 테스트 독립성, 변경 범위를 확인하고 발견한 결함은 회귀 케이스와 함께 수정한다.
8. `qa/REPORT_TEMPLATE.md`를 사용해 `qa/reports/RS-005.md`를 작성하고 `qa/TEST_CASES.csv`에서 자신의 케이스 상태를 갱신한다. `tickets/RS-005.md` 및 INDEX의 완료 증거도 기록한다. 실행되지 않은 외부 환경 검증은 NOT RUN/BLOCKED로 남긴다.
9. 기존 완료 조건과 TEST_PLAN의 품질 게이트를 모두 충족할 때만 DONE으로 판단한다. 실제 Git 권한이 있을 때만 자기 변경을 커밋하고 push/merge/후속 티켓 착수는 하지 않는다.
