# RS-007 실행 프롬프트

당신은 RoomShare 프로젝트의 소프트웨어 개발 Agent다. 현재 저장소에서 **RS-007 — 관리자 모바일 웹**만 실제 구현하라. 단순 설계 제안이나 코드 예시만 작성하지 말고, 필요한 파일을 수정하고 테스트를 실행하라.

## 먼저 읽을 파일
`AGENTS.md`, `README.md`, `docs/REQUIREMENTS.md`, `docs/DECISIONS.md`, `docs/DESIGN.md`, `docs/API.md`, `docs/DEPLOYMENT.md`, `tickets/INDEX.md`, `tickets/RS-007.md`, `prompts/COMMON.md`.
공통 작업 지침을 적용하며 선행 티켓(RS-006)의 실제 완료 및 산출물을 검증하라. 사용자 변경 보존 및 테스트 전용 DB 사용. 운영 서버 변경/push/merge 금지.

## 이번 작업의 목표
별도 관리자 주소에서 예약 및 차단일을 관리할 수 있는 모바일 UI 구현.

## 수행할 작업
1. `/admin`은 RS-006 guard 적용 후 렌더링. 필요 시 관리자 호스트 `/` 리다이렉트는 RS-008과 합의. 공개 페이지 링크 추가 금지.
2. 월별 달력, 예약 목록(날짜, 이름, 메모, 상태), 등록/수정/취소 폼, 차단일 등록/해제, 로그 페이지네이션, 예약 가능 기간 설정 UI 구현. 모든 변경은 관리자 API 사용. 달력 상태 조회 방식은 기존 계약 활용 또는 API 문서에 합의된 최소 확장만 사용.
3. 예약 수정은 기존 전체 선택 날짜를 표시하고 저장 전 차이를 확인할 수 있게 한다. 월 단위 목록에서 월을 넘는 예약을 잘라서 수정하지 않는다. 취소/차단 해제는 확인 UI 후 요청한다.
4. RS-006에서 합의한 CSRF 토큰 전달과 Origin 검증에 맞춘 fetch 사용. 토큰/해시는 표시하거나 브라우저 영구 저장하지 않는다. 사용자 입력은 안전하게 렌더링.
5. 403(접근 불가), 409(충돌), 422(입력), 429/503 및 네트워크 오류 처리. 수정 실패 시 기존 상태 유지 및 입력 보존, 성공 후 해당 목록/달력/로그 갱신. 중복 제출 방지.
6. 360px에서 관리 화면이 넘치지 않도록 목록 카드 또는 반응형 구성. 버튼/레이블/포커스 접근성. 관리자 HTML과 데이터 no-store, 공개 페이지에 관리자 정보 노출 없음.

## 변경 범위
app/templates/admin/index.html, app/templates/admin/base.html, app/static/css/admin.css, app/static/js/admin.js, app/routers/admin.py, tests/test_admin_page.py, tests/manual/admin-ui.md
파일명은 제안이며 실제 저장소 구조에 맞추되 범위를 확대하지 마라.

## 테스트 요구
- 인증 없는 관리자 페이지 거부, 유효 관리자 페이지 접근/CSRF 발급.
- 예약 생성/수정/취소, 여러 월에 걸친 기존 날짜 유지, 차단/해제, 로그 이동, 설정 변경.
- 삭제 확인 취소 시 요청 없음, 409 시 원래 데이터 유지, 403/503/네트워크 안내.
- 360px/390px/데스크톱 브라우저 실제 검증, HTML 삽입 공격 방지, 사용자 화면 관리자 링크 없음.

## 심화 실행 절차 (v2)
반드시 `docs/TEST_PLAN.md`, `qa/specs/RS-007.md`, `qa/REPORT_TEMPLATE.md`, `qa/TRACEABILITY.md`를 추가로 읽어라. 다음 지침은 기존 티켓의 구현 범위와 함께 적용한다.

1. 화면별 API 매핑을 표로 확정한다: 예약 목록/등록/수정/취소, 차단일/해제, 로그, 설정. 관리자 달력 조회에 필요한 계약이 없으면 최소 변경을 RS-006과 합의하고 문서와 테스트를 동시에 갱신한다.
2. 편집 상태는 서버 원본 스냅샷과 사용자 수정본을 분리한다. 월 필터가 예약 전체 날짜를 잘라내지 않도록 한다. 저장 중 중복 입력 방지, 실패 시 원본 유지 및 편집본 보존, 성공 후 목록/달력/이력 재조회.
3. CSRF 값은 합의된 메모리/DOM 전달 방식으로만 관리하고 사용자 취소 토큰과 혼동하지 않는다. 모든 변경 요청의 실패/만료 UI와 재인증 안내를 준비하되 로그인 페이지를 추가하지 않는다.
4. 브라우저 테스트는 인증된 격리 환경에서 수행하고 인증 우회 경로를 배포하지 않는다. 실제 mTLS 종단 검증은 RS-008로 전달한다.

### 구현 및 테스트 수행 순서
1. 선행 산출물과 현재 코드를 확인하고 이번 티켓의 파일/인터페이스/테스트 계획을 작성한다. 아직 구현되지 않은 후속 기능은 범위에 넣지 않는다.
2. 다음 명세를 기준으로 가능한 자동화 테스트를 작성한다. 미구현 기능의 실패 또는 기존 기준선을 실제 실행하고, 테스트의 실패 이유를 기록한다. 존재하지 않는 테스트를 실행했다고 주장하지 않는다.
3. 기능을 구현하고 정상/오류/경계 케이스를 반복 실행한다. 실제 SQLite가 필요한 테스트에 mock DB를 쓰지 않는다. 수동 케이스는 실제 환경에서만 PASS 처리한다.
4. 명세의 기대 결과를 상태·응답·DB/로그 등 해당 관찰 지점에서 직접 검증한다. 관련 TC ID를 테스트명, 파라미터 ID 또는 보고서에 연결한다.
5. 아래 목록 전체와 상세 명세의 사전 조건·절차를 확인한다. 케이스를 임의 삭제하거나 skip으로 통과시키지 않는다.
- `TC-007-01` [api/local] 관리자 페이지 권한 → HTML/CSRF/개인 데이터 거부; 정적 파일에는 민감 데이터 없음
- `TC-007-02` [e2e/local] 정상 관리자 페이지 → 관리자 UI 로딩, 변경 요청에 합의된 CSRF 전달
- `TC-007-03` [e2e/local] 등록 및 수정 → 캘린더/목록/이력 갱신, 서버 데이터와 일치
- `TC-007-04` [e2e/local] 월 경계 예약 수정 → 두 날짜 모두 유지; 전체 날짜 편집 UI 확인
- `TC-007-05` [e2e/local] 취소 확인 → 첫 요청 0건, 두 번째 한 건, 점유 해제 및 상태 갱신
- `TC-007-06` [e2e/local] 차단 및 해제 → 상태 변경 정확, 기존 예약 삭제 없음, 해제 확인 제공
- `TC-007-07` [e2e/local] 수정 충돌 복구 → 409 안내, 수정 입력 보존, 기존 예약 그대로, 재조회 가능
- `TC-007-08` [e2e/local] 로그 및 설정 → 정렬/페이지 표시 정확, 성공 값 표시, 기존 점유 보존
- `TC-007-09` [e2e/local] 권한/CSRF 실패 → 403 안내, 성공 표시/자동 재제출 없음, DB 불변
- `TC-007-10` [e2e/local] 네트워크 및 서버 오류 → 적절한 안내/입력 보존/버튼 복구, 중복 제출 없음
- `TC-007-11` [e2e/local] 안전한 렌더링 → 문자열만 표시, 실행 없음, 민감 응답 캐시/토큰 저장 없음
- `TC-007-12` [e2e/local] 모바일 관리자 UI → 가로 overflow 없음, 버튼 접근 및 포커스 정상
- `TC-007-13` [manual/device] 실제 관리자 모바일 → 기기별 결과 및 인증 환경 구분 기록
6. 대상 테스트 및 전체 pytest를 실행하고 결과/종료 코드/수집 건수/실패·skip을 기록한다. 브라우저, Nginx, OCI 등 별도 테스트는 실제 명령 및 환경 증거를 남긴다.
7. 자기 변경에 대한 코드 리뷰를 수행한다. 요구사항 및 API 계약, 오류 경계, 데이터 무결성, 보안, 불필요한 의존성, 테스트 독립성, 변경 범위를 확인하고 발견한 결함은 회귀 케이스와 함께 수정한다.
8. `qa/REPORT_TEMPLATE.md`를 사용해 `qa/reports/RS-007.md`를 작성하고 `qa/TEST_CASES.csv`에서 자신의 케이스 상태를 갱신한다. `tickets/RS-007.md` 및 INDEX의 완료 증거도 기록한다. 실행되지 않은 외부 환경 검증은 NOT RUN/BLOCKED로 남긴다.
9. 기존 완료 조건과 TEST_PLAN의 품질 게이트를 모두 충족할 때만 DONE으로 판단한다. 실제 Git 권한이 있을 때만 자기 변경을 커밋하고 push/merge/후속 티켓 착수는 하지 않는다.

- [ ] 관리자만 페이지 접근 가능.
- [ ] 모든 관리자 기능의 정상/실패 흐름 처리.
- [ ] 삭제 확인 및 수정 충돌 시 입력/기존 예약 보존.

위 조건을 증거로 검증한 후 `python -m pytest -q`와 `git diff --check`를 실행하라. 실행 불가/실패는 사실대로 기록하라. `tickets/RS-007.md`와 `tickets/INDEX.md`의 상태와 완료 보고를 갱신하라. Git 작업이 허용될 때 브랜치 `feature/RS-007-admin-ui`에서 자기 변경만 `feat(admin): add mobile management interface (RS-007)` 형식으로 커밋하라. 후속 티켓은 자동 시작하지 마라.
