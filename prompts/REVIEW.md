# 독립 리뷰 Agent 프롬프트

대상 티켓 번호를 입력받아 해당 티켓의 구현과 테스트를 독립 검토하라. AGENTS.md, prompts/COMMON.md, docs/, tickets/INDEX.md, 대상 tickets/RS-XXX.md, prompts/RS-XXX.md, qa/specs/RS-XXX.md, qa/reports/RS-XXX.md(존재하는 경우), qa/TEST_CASES.csv를 읽어라. AGENTS.md의 필수 문서 목록도 확인하라. 보고서가 없으면 그 사실을 기록하고 증거를 추정하지 마라.

1. 실제 변경 diff와 선행 계약을 비교하고 대상 커밋과 보고서 실행 커밋이 일치하는지 확인하라.
2. 각 TC에 실제 test 함수 또는 수동 증거가 있는지 확인하고 assertion이 기대 결과를 충분히 검증하는지 검토하라. 동시성은 독립 연결 및 실제 경쟁인지 확인하라.
3. 가능하면 격리 환경에서 대상 테스트와 전체 회귀를 직접 재실행하라. 명령/종료 코드/결과를 기록하라. 외부 환경은 접근 권한 없으면 NOT RUN.
4. 날짜, 원자성, 입력, 관리자 권한, 로그·토큰, 복원 안전성 중 해당되는 사항을 중점 검토하라.
5. 발견 사항을 severity(릴리스 차단/중요/경미), 파일:라인, 재현 절차, 관련 TC, 기대/실제 결과, 수정 제안 순서로 보고하라.
6. 결과는 APPROVE / REQUEST CHANGES / BLOCKED로 기록하라. 미검증 필수 사항을 승인하지 마라. 소스/테스트 수정, 티켓/CSV 상태 변경, 보고서 파일 저장, 커밋·push·merge는 별도 요청 없이는 하지 마라. 격리된 임시 테스트 산출물은 허용한다. 리뷰 결과는 응답으로 보고하라.
