# RS-010 — PWA 홈 화면 지원

- 상태: BLOCKED (선행 RS-009 미완료; PWA 구현 미착수)
- 우선순위: P2
- 선행 티켓: RS-009
- 관련 요구사항: 선택 확장
- 브랜치 제안: `feature/RS-010-pwa`
- 커밋 예시: `feat(pwa): support home screen installation (RS-010)`

## 목표
MVP 완료 후 선택적으로 사용자 홈 화면 추가를 제공. 오프라인 예약은 지원하지 않는다.

## 예상 변경 파일 (제안)
app/static/manifest.webmanifest, app/static/icons/, app/static/js/sw.js 또는 공개 SW 경로, app/templates/index.html, tests/test_pwa.py, tests/manual/pwa.md

## 구현 범위 및 세부 작업
1. RS-009 완료와 PWA 작업 승인 여부 확인. 사용자 호스트에만 manifest, 앱 이름, start_url, scope, 로컬 아이콘 연결. 관리자 템플릿에는 등록하지 않는다.
2. Service worker는 공개 정적 파일 allowlist만 캐시하도록 제한한다. 페이지 HTML/달력 API/예약/취소/관리자/토큰/개인정보 응답, 비 GET 요청은 캐시 및 오프라인 재생 금지. 이전 cache version 정리 및 배포 시 갱신 계획.
3. 네트워크 연결이 없으면 예약/취소가 불가능하다고 명확히 표시한다. 서버 응답 없이는 성공 상태 표시 금지. background sync/자동 재전송/오프라인 예약 저장 금지.
4. 기존 공개 모바일 UI, 보안 헤더 및 no-store와 충돌하지 않도록 한다. HTTPS 테스트 환경에서 설치/업데이트 확인. iOS Safari와 Android Chrome의 실제 확인 결과를 구분한다.

## 필수 테스트 시나리오
- manifest/아이콘/서비스워커 정상 경로 및 공개 호스트 scope 검증.
- 관리자/HTML/API/POST/토큰 응답 캐시 부재(Cache Storage 검사).
- 오프라인 예약/취소 실패 안내 및 재연결 후 수동 조회, 자동 제출 없음.
- cache 갱신 및 이전 정적 파일 제거, 기존 예약 흐름 회귀 테스트.
- iOS/Android 실제 홈 화면 추가 확인, 없는 장치는 NOT RUN.

## 후속 작업 인계
PWA 미적용 MVP와의 차이, 브라우저 설치 검증 및 캐시 정책을 운영 문서에 전달.

## 구현 심화 지침 (v2, 제안)
1. 사용자 호스트에만 manifest/아이콘/SW 등록한다. scope와 실제 경로를 브라우저에서 검증하고 관리자 호스트와 공유되는 경우 캐시 정책을 재검토한다. 실제 지원 차이는 설치 테스트 결과로만 기록한다.
2. 정적 리소스 GET allowlist에만 cache 전략을 적용한다. HTML 및 API 요청은 네트워크 전용이며 오프라인 때 성공 응답을 합성하지 않는다. cache 이름 prefix/version으로 다른 앱의 캐시를 삭제하지 않는다.
3. SW 갱신과 이전 리소스 제거를 검증한다. offline→online 전환은 사용자가 명시적으로 재조회/재시도하도록 하고 background sync, 자동 재전송, 예약 내용 저장을 추가하지 않는다.
4. 브라우저 지원이 없는 경우 기존 웹 기능을 그대로 사용할 수 있어야 한다. PWA 실패가 MVP 예약 동작에 영향을 주면 롤백/비활성화 방법을 제공한다.
