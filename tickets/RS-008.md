## 구현 범위 및 세부 작업
1. 개발 Ubuntu와 OCI의 Python/OS/RAM/디스크/네트워크/권한을 구분하여 실제 확인 가능한 항목만 기록. 운영 경로 /opt/roomshare, /var/lib/roomshare, /etc/roomshare, 비권한 서비스 계정, DB/설정 권한, venv lock 설치 및 명시적 마이그레이션. 환경별 설정 예제를 작성하고 실제 키/인증서/비밀은 포함하지 않는다.
2. systemd unit은 단일 worker, loopback 또는 권한 제한 Unix socket, 재시작 정책, 로그, 작업 디렉터리, 환경 파일 및 최소 쓰기 경로 구성. 백엔드 포트 외부 공개 금지. 배포 스크립트는 실패 시 nonzero, 오류 출력, 재실행 안전성을 확보한다. 실행 중 데이터베이스를 덮어쓰지 않는다.
3. Nginx 사용자/관리자 vhost 별도, HTTPS, HTTP 처리, 기본/알 수 없는 호스트 거부, 사용자 호스트 관리자 UI/API 차단. 관리자 호스트 mTLS 검증 성공 후에만 접근 신호를 전달한다. 사용자 입력의 내부 헤더 및 Forwarded 헤더는 제거/덮어쓴다. 앱 guard와 동일 계약. 요청 크기/빈도 제한, 민감 응답 캐시 방지, TLS 개인키 및 CA 관리/폐기 문서. mTLS 대신 사설망 선택은 별도 승인 전 임시 변경 금지.
4. 인증서/DNS 예시는 템플릿으로 표시. 테스트용 CA/client cert는 별도 임시 경로에서만 생성. nginx -t 및 로컬 TLS 경로 테스트; 운영 설정을 자동 reload하지 않는다. OCI 보안 목록/NSG/OS 방화벽과 SSH 관리 IP, 443/필요 시 80만 허용, 실제 변경은 운영자 승인 필요.
5. SQLite backup API 또는 sqlite3 .backup으로 일관된 스냅샷 생성, 권한 제한, 실패/무결성 검증, 일일 timer, 보존 기간 설정(이력 90일과 백업 보존 정책은 서로 구분하고 미확정 명시). WAL 파일 단순 복사 금지. 복원은 임시 DB에 먼저 검증, 운영 복원은 서비스 정지/기존 DB 보존/명시적 확인 후 수행.
6. 로컬 배포 → 테스트 → OCI 이전 계획. 배포 전 백업, 릴리스 버전/lock, DB 스키마 호환성 점검, 상태 확인, 이전 코드+호환 DB로 rollback 절차. 실제 OCI 권한 없으면 접속/배포/성능 검증을 NOT RUN으로 표시.

- 외부 인터페이스 백엔드 직접 접속 실패(실제 환경별 검증), 서비스 재시작 후 예약 유지.
- WAL 사용 중 백업 생성/무결성 확인/격리된 경로 복원 후 예약 및 설정 비교, 손상 백업 복원 거부.

- OCI DNS/TLS/네트워크/실제 자원 검증은 접근 시만 실행.

## 구현 심화 지침 (v2, 제안)
1. 설치, 구성 생성, 마이그레이션, 서비스 전환, 검증, 롤백 단계를 분리한 runbook을 작성한다. 기존 설치를 다시 실행할 때 DB/환경 설정/인증서 덮어쓰기 금지. 실제 sudo/systemd/Nginx 변경은 승인된 스테이징에서만 수행한다.
2. Nginx 테스트는 운영 config가 아닌 격리 config와 테스트 CA로 수행한다. 실제 Host/SNI, 프록시가 덮어쓴 헤더 및 앱 guard를 함께 검증한다. 외부 백엔드 차단은 별도 클라이언트에서 측정한다. 실제 인증서 만료/갱신/폐기 절차는 운영자 승인 필요.
3. backup은 일관된 SQLite snapshot으로 생성하며 임시 파일에 기록 후 검증 성공 시에만 최종 이름으로 이동한다. 소유권/권한, 실패 로그, 보존 기간, 별도 위치 및 복구 순서를 작성한다. 복원 대상은 기본 임시 경로이며 운영 복원은 확인/정지/원본 보존/검증이 선행되어야 한다.
4. 배포 결과를 LOCAL-STAGING과 OCI로 분리한다. 환경 차이, 실제 DB/인증서 이동 방법, downtime 및 이전 릴리스 호환성을 점검한다. 실제 운영 데이터 또는 키를 Agent 산출물로 복사하지 않는다.
