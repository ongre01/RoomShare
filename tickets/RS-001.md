## 목표
실행 가능한 최소 FastAPI 앱과 재현 가능한 로컬 개발 환경 구축. 예약 기능은 구현하지 않는다.

## 예상 변경 파일 (제안)
app/main.py, app/config.py, app/templates/base.html, app/static/, tests/conftest.py, tests/test_health.py, requirements*.in, requirements*.lock, README.md, .env.example

## 구현 범위 및 세부 작업
1. 앱 팩토리 `create_app`과 ASGI 진입점 구현. 설정을 테스트에서 주입할 수 있게 분리한다. import만으로 운영 DB를 생성하지 않는다.
2. .env.example의 DB_PATH, TIMEZONE, PUBLIC_HOST, ADMIN_HOST, BOOKING_HORIZON_DAYS, ADMIN_ACCESS를 읽는다. 환경 변수와 .env 로딩 방식/우선순위를 문서화한다. timezone은 Asia/Seoul, 기본 관리자 접근은 deny, 두 호스트는 서로 달라야 한다. 기간은 양의 정수이며 빈 경로/잘못된 호스트/지원하지 않는 관리자 모드 등은 명확한 시작 오류로 처리한다.
3. Jinja2 템플릿/정적 파일 경로를 소스 위치 기준으로 해석하고 기본 레이아웃에 모바일 viewport를 포함한다. GET /healthz는 최소 JSON 응답만 반환한다. 공개 `/`는 후속 티켓이 구현할 자리만 제공한다.
4. Python 3.11 이상 초기 목표에 맞춰 실제 `python --version` 기록, venv, 런타임/개발 lock 파일 생성 방식과 설치 명령을 README에 작성한다. lock 버전을 추측하지 말고 실제 설치·호환성 검증한다.
5. 테스트 fixture에서 임시 디렉터리/설정 주입을 가능하게 한다. 외부 인터페이스 대신 로컬 기본 바인딩 사용. 실제 관리자 bypass를 개발 편의로 만들지 않는다.

## 필수 테스트 시나리오
- 정상 설정에서 앱 생성 및 GET /healthz 200, 응답에 경로/환경 변수/버전/비밀 없음.
- 잘못된 기간(0, 음수, 문자), 동일 호스트, 잘못된 timezone 및 관리자 모드의 시작 실패.
- 다른 작업 디렉터리에서도 템플릿/정적 파일 경로 정상.
- 깨끗한 venv에서 lock 설치 후 README 명령으로 실행, 로컬 HTTP 확인, pytest smoke 및 전체 테스트.

## 구현 심화 지침 (v2, 제안)
1. 먼저 저장소 실제 상태를 확인하고 설정 객체의 공개 필드/환경 변수 매핑 및 우선순위를 명시한다. `create_app(settings=...)` 형태의 주입 가능한 계약을 제안하되 실제 이름은 문서에 확정한다. 모듈 로딩, 앱 생성, lifespan의 부작용을 각각 구분한다.
2. 가상환경/lock 생성·설치 절차를 분리한다. 현재 환경 Python 버전과 SQLite 버전을 기록하고 실제 설치한 버전으로 lock을 만든다. 테스트용 도구와 운영 의존성 분리; 설치 불가 시 버전을 지어내지 않는다.
3. `tests/conftest.py`에 임시 설정 fixture, 이후 DB fixture 확장점과 앱 client fixture를 마련한다. RS-002부터 마이그레이션된 DB를 연결한다. 아직 없는 기능의 가짜 구현으로 테스트를 통과시키지 않는다.
4. healthz는 최소 JSON(예: `{ "status": "ok" }`, 정확한 형식 문서화)을 반환하며 내부 상태를 노출하지 않는다. 초기 관리자 미구현 경로와 RS-006 이후 권한 guard의 검증 범위를 구분한다.
